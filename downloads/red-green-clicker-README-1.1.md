## 1.1 改动

- 默认使用宽高各 50% 的采集面，像素数约为原来的四分之一。监测坐标自动映射到采集画面，点击坐标仍是原屏幕坐标。
- 可选 100% 原分辨率、50% 默认模式、25% 实验模式。不整除的特殊尺寸会回退到可保持精确宽高比的档位，实际档位显示在监测状态。
- 默认由识别线程直接提交安卓手势，减少一次主线程消息排队；可关闭“识别线程直接提交点击”作为兼容模式对照。
- 点击手势预先构建；悬浮条边界由主线程缓存，识别线程不读取 View。拖动控制条会暂停监测，停止/选点后的旧任务不会继续提交点击。
- 监测阶段只在状态变化时更新悬浮文字，减少反复刷新 RGB 文本；保留第一帧触发、最新帧获取和旧帧丢弃。
- 新增单次/连续 10 次测试、分段耗时、中位数、P95、最小/最大值。总耗时仍是“提交变色 → 目标收到点击”，没有通过更换计时起点来宣称加速。
- 同包名、同签名、versionCode 2，可以覆盖升级 1.0。旧版本 APK 保留下载。安卓通常不允许直接降级安装；回退 1.0 可能需要先卸载 1.1，卸载会清除设置。

## 安装与第一次使用

1. 用手机自带浏览器或 Chrome 打开下载页，下载 1.1 APK。APK 下载失败可尝试 ZIP，下载后解压并打开其中的 APK。
2. 安装后打开“红绿快点”。点“① 开启无障碍点击”，阅读用途说明后在系统中开启该服务。
3. 部分系统对浏览器下载的应用限制无障碍设置，可先到应用信息菜单里允许受限设置，再返回开启。入口以手机系统为准。
4. 回到应用，点“② 开启屏幕采集”。授权范围请选择“整个屏幕”；Android 14 及以上会优先请求系统的全屏采集配置。
5. 进入目标页面，通过悬浮条分别选择监测点和点击点。监测点选在红/绿色块内部，避开边缘、文字、阴影和悬浮条。
6. 将悬浮条拖到空白位置，按“开始”。必须先看到红色，再变绿才触发。默认只点击一次，循环模式需重新见红后才可再触发。

“暂停”停止判色与新点击任务；“停止”、通知里的停止按钮和“收起”关闭采集。屏幕旋转、分辨率改变或系统结束投屏后，重新授权并选点。

## 推荐先测的两组

默认组：50% 采集、直达开启、1 帧触发、3×3 像素平均。

对照组：100% 采集、直达关闭，其余参数相同。改变采集分辨率后必须保存设置并重新授权采集，再进入测试页。

测试页点“连续10次”，程序会自动设置两个测试坐标、等待识别红色、再变绿并统计自动点击。请勿手动触碰色块，移开悬浮条并保持本页在前台。测试会覆盖之前的两个选点，使用其他目标前请重新选点。离开测试页会停止本组测试。

先比较两组中位数和 P95，再逐一切换分辨率或点击模式，避免同时改很多参数而无法判断来源。25% 只是实验选项；小色块有可能因缩小采集而混色，应切回 100% 并确认识别稳定。

## 分段计时说明

全部阶段使用同一个进程内的 System.nanoTime，不将设备 Image 时间戳直接与应用时钟相减。

- **渲染/采集/等待取帧**：测试页提交变色请求，到取得最终触发判定那一帧。包含等待绘制、系统合成、采集、回调调度和取帧；如果选择了多帧确认，还包含前面的确认等待。不是纯粹的屏幕采集耗时。
- **其中取帧 API**：采集回调开始到取得触发帧，已包含在上面的第一段，不能重复相加。取帧调用期间也可能收到更新的帧，因此以取得帧的时刻作为分段边界。
- **采样＋判色**：取得触发帧，到绿色触发判定完成。
- **判色→提交点击**：触发判定完成，到调用 dispatchGesture。兼容模式的主线程排队包含在这里。
- **提交→目标收到点击**：提交手势到测试色块的 onClick；包含输入系统与目标应用调度。
- **总耗时**：变色请求到 onClick，与 1.0 同一起点。它不是摄像机测得的真实显示发光到触摸延迟，也不代表目标网络请求已完成。

P95 使用最近秩，10 次时会接近/等于这组最大值。超时会停止测试并保留已成功的数量，不把失败样本伪装成零耗时；请连同成功次数一起看结果。

不存在固定延迟保证。降低分辨率和减少线程中转的收益，取决于手机系统、实际采集帧率、温度、负载和目标页面。屏幕高刷新率不代表系统采集一定同样高帧率。

## 隐私与限制

屏幕图像只保留在本机内存，不保存、不上传；应用没有联网权限。计时数据也只在内存中。无障碍只用于你指定位置的点击，不读取控件内容。

受系统保护的黑屏页面不能识别。锁屏、其他投屏任务、厂商回收服务可能结束采集。坐标不会理解页面布局或按钮含义；目标位置移动后要重新选点。

HSV 判色过滤低饱和、过暗画面，适合清晰红/绿色块。3×3 指采集画面中的像素；50% 时覆盖更大的原屏区域，小色块可改为 1 像素或原分辨率。首次已是绿色不会触发。

## 构建与验证

源码无第三方运行库依赖。需要 Python 3、JDK 11+、Android platform 30+、Build Tools 35。配置 JAVA_HOME、ANDROID_JAR、ANDROID_BUILD_TOOLS 后运行 python build.py，可用 COLOR_TAP_BUILD 指定构建目录。

构建脚本先运行判色/状态、坐标缩放、带行/像素步长的采样、统计和计时口径测试，然后编译、DEX、对齐、签名及校验。签名私钥不包含在源码压缩包或仓库，位于本机工作构建目录。重新构建时请使用原签名密钥以覆盖安装。

已完成纯 Java 检查、APK 构建与签名校验；当前没有连接中的安卓设备，端到端延迟和厂商兼容性需要实际手机验证。
